KatsuTun Premium - changelog

1.4.0
- SlowDNS (dnstt-server) masuk menu SSH: satu akun SSH langsung berlaku untuk
  SSH dan SlowDNS. Nameserver, keypair, service systemd, redirect UDP 53->5300,
  cek delegasi NS, dan tampilan public key di layar akun.
- Perbaikan penyebab game tidak bisa: proxy_read_timeout nginx 3600s,
  badvpn-udpgw lewat systemd (auto-restart, 7100-7900), idle timeout WS 15 menit,
  config squid panel, fail2ban ignoreip, tun-mtu 1400 + mssfix 1360, ip_forward
  persisten, MSS clamp. Tersedia otomatis lewat: katsu-gamecheck --fix
- UI baru: title bar berisi versi, badge status rata kanan, heading grup,
  sudut membulat, footer konsisten, gap antar kolom lebih rapi.
- katsu-gamecheck: diagnostik game read-only + mode --fix.

1.4.1
- katsu-gamecheck: FAIL "rc.local tidak memuat badvpn-udpgw" tidak lagi muncul
  pada VPS yang sudah migrasi ke unit systemd (autostart dinilai dari systemd
  atau rc.local, mana yang dipakai).
- Parser cron: assignment (SHELL=, PATH=) tidak lagi dianggap jadwal; reboot
  harian 03:00 dilaporkan normal, hanya interval < 6 jam yang diperingatkan.
- wondershaper: /home/limit yang basi tidak lagi dianggap throttle aktif
  (dicek lewat service dan qdisc tc).
- Unit openvpn-server@ yang "activating" kini menampilkan error jurnal +
  terjemahannya (comp-lzo di OpenVPN 2.6, TUN/TAP tidak ada, port bentrok,
  plugin PAM, file sertifikat hilang).
- --fix: menghentikan proses badvpn lama dari `screen` (penyebab unit systemd
  berputar di "activating"), melaporkan port UDPGW yang benar-benar aktif,
  memverifikasi OpenVPN setelah restart, dan memasang sshd
  ClientAliveInterval 30 + ClientAliveCountMax 6.
- --fix kini ringkas (hanya perubahan + sisa temuan); --verbose untuk detail.

Update Your Script

1.4.2
- Kartu SERVER STATUS tidak lagi asal menulis OVPN TCP/UDP OFFLINE: status
  dibaca dari unit systemd yang benar-benar ada (openvpn-server@ di OpenVPN
  2.5+, openvpn@ di 2.4) dan dari port yang benar-benar listen (1194/2200).
- katsu-gamecheck --fix sekarang menyebut sebab nyata OpenVPN gagal: config
  divalidasi (openvpn --test-crypto), bukan cuma membaca jurnal yang sering
  kosong.
- --fix memperbaiki yang bisa otomatis: comp-lzo yang ditolak versi OpenVPN
  dimatikan di server sekaligus di semua client .ovpn (client harus unduh
  ulang config), dan path plugin openvpn-plugin-auth-pam.so yang salah
  dibetulkan sesuai lokasi paket.
- VPS dengan paket OpenVPN 2.4 (template openvpn@): config di
  /etc/openvpn/server/*.conf otomatis disymlink ke /etc/openvpn/<nama>.conf
  supaya unit-nya bisa dijalankan.
- Diagnostik: kalau unit OpenVPN mati tanpa error di jurnal, tampil saran
  menjalankan --fix; kalau config ada tapi unit systemd tidak ada, itu
  dilaporkan sebagai temuan.
